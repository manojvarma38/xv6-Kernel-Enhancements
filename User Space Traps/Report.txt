Internal Working of User Space Traps :
---------------------------------------

A user program calls sigalarm(ticks, handler).

The kernel stores the alarm interval, remaining ticks, and handler address inside the process’s struct proc.

Every clock tick generates a timer interrupt, handled in usertrap(). On each tick, if the current process has an alarm armed and is not already inside a handler, the kernel decrements the countdown.

When the countdown reaches zero, the kernel prepares to deliver the alarm handler.

The kernel saves the current process state by copying the trapframe into a backup field. The process is marked as alarm_on to prevent re-entry.

The kernel sets the process’s program counter (epc) to the handler address so that, on return to user mode, execution continues at the user-defined handler function.

The handler runs like a normal user function, but was entered asynchronously due to the timer interrupt.

The user must call sigreturn() at the end of the handler to restore the interrupted context.

When sigreturn is called, the kernel copies back the saved registers from the backup trapframe to the current trapframe.

The alarm_on flag is cleared, and the countdown is reset to the alarm interval, allowing future alarms.

The user program resumes from the exact instruction where it was interrupted.
